# 自動ダウンロードの廃止

録画したクリップを `~/Downloads` へ自動保存する機能をやめる。
2026-09-12 の「ページ内操作と自動保存」設計 §3 を**取り消す**。

## 1. なぜやめるか

ウェブストアは、サイトの利用規約に反してストリーミング動画を保存させる拡張を
禁じている。**ディスクへ動画ファイルを書き出す経路が、この拡張でいちばん
「ダウンローダ」に見える部分**だった。公開を目指すにあたって外す。

利用者の判断であり、技術上の必要から外すわけではない。

## 2. 何が無くなるか

`saveToDownloads` と、それを呼ぶ `finishRecording` の一節。
**これがディスクへ書く唯一の経路**だったので、廃止後は動画ファイルが
利用者の端末のファイルシステムに置かれることは一切なくなる。

クリップは今までどおり IndexedDB に入り、X の投稿画面へ添付される。
そこは変わらない。

## 3. 名前と文言が嘘になる

`downloadable` という状態名は「ダウンロードできる」という意味だった。
ダウンロードできるものが無くなるので、**名前を変える**。

| 旧 | 新 |
|---|---|
| `downloadable` | `degraded` |

`degraded` は設計ドキュメントと README で既に使ってきた語 (degraded path) で、
「録画は成功したが通常の投稿フローに乗せられなかった」という意味に合う。

文言も同じ理由で書き直す。

| 理由 | 旧 | 新 |
|---|---|---|
| `x-attach-failed` | ファイルをダウンロードして手動で添付してください | 「X にもう一度投稿」でやり直せます |
| `mp4-unsupported` | 変換してご利用ください | このブラウザでは X に添付できる形式で録画できません |

## 4. 失うもの

**`mp4-unsupported` が行き止まりになる。** これまでは WebM ファイルが手元に
残り、変換して手で添付する道があった。廃止後はその道が無い。録画に払った
実時間が無駄になる。

該当するのは `video/mp4;codecs="avc1.640028,mp4a.40.2"` を録れないブラウザ
(プロプライエタリコーデック無しの Linux Chromium など)。macOS / Windows の
Chrome では起きない。

**この経路では「X にもう一度投稿」を押しても通らない。** 押せてしまうが、
同じ理由でまた失敗する。状態機械は理由 (`reason`) を持つが、操作の出し分けは
状態の種類だけを見ているため。ここは分けない — 分岐を足す価値より、
起きない環境のために構造を複雑にする損の方が大きい。

`x-attach-failed` は行き止まりではない。「X にもう一度投稿」で投稿画面を
開き直して添付をやり直せる。

## 5. 触る場所

| ファイル | 何を |
|---|---|
| `src/content/save.ts` | 削除 |
| `src/content/youtube.ts` | 保存の呼び出しと import を外す |
| `src/shared/types.ts` | `downloadable` → `degraded` |
| `src/background/state.ts` | 同上 |
| `src/popup/view.ts` | 同上と文言 |
| `src/content/actions.ts` | 同上 |
| `tests/content/save.test.ts` | 削除 |

`display-matrix.ts` (表示行列の修正) と `filename.ts` は**残す**。
どちらも X への添付で使っている。

## 6. テスト

- 録画が終わってもアンカー要素が作られないこと (`click` が呼ばれないこと)
- `degraded` の 2 つの理由がそれぞれ正しい文言になること
- 状態機械の遷移は名前を変えるだけで、形は変わらないこと
