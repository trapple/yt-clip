# 操作をページ内へ移し、作った切り抜きを使い回せるようにする

実機運用で出た 4 つの要望に対する設計。

1. 投稿後に YouTube に戻ると IN/OUT が触れなくなる。範囲も録画済みクリップも
   再利用したい。投稿のやり直しもしたい
2. 録画した動画を自動で保存したい
3. IN/OUT 決定後の操作を、拡張のポップアップではなくブラウザ画面内で完結させたい
4. IN/OUT まわりの見た目が安っぽい

## 1. 背景: なぜ投稿後に触れなくなるのか

`ATTACHED` を受けると状態機械が `idle` を返す (`src/background/state.ts:122`)。
`idle` には範囲もクリップ参照も無いため、content script 側は範囲を失い、
拡大バーは `canAdjustRange()` の条件 (`kind === "ready"` 相当) を満たさなくなる。
**仕様どおりの動作だが、実際の使い方に合っていない。** 同じ動画から続けて
切り抜きを作る / 同じクリップを投稿し直す、どちらも日常的に起きる。

## 2. 投稿後の再利用

### 2.1 新しい状態 `posted`

`ATTACHED` の行き先を `idle` から **`posted`** に変える。

```typescript
| { kind: "posted"; range: ClipRange; meta: VideoMeta; clipId: string }
```

`preview` と同じ中身を持つが、**表示が変わる** (「録画できました」ではなく
「X に添付しました」) ため別の状態にする。`preview` にフラグを足す形にすると、
状態機械の網羅性チェックが効かなくなる。

### 2.2 `posted` から出る道

| 操作 | 行き先 | クリップ |
|------|--------|----------|
| 再投稿 (`POST`) | `composing` | 保持 |
| 取り直し (`RETAKE`) | `ready` | 外す |
| 範囲を変える (`ADJUST_RANGE`) | `ready` | 外す |
| 新しい IN (`MARK_IN`) | `ready` | 外す |
| OUT を打ち直す (`MARK_OUT`) | `ready` | 外す |

**範囲を変えたらクリップは外す。** そのクリップは古い範囲のもので、持ち続けると
「画面に出ている範囲」と「投稿される中身」が食い違う。このプロジェクトが
繰り返し踏んできた形なので、状態の側で起こらないようにする。自動保存 (§3) が
あるためファイル自体は手元に残る。

### 2.3 添付に失敗した後もやり直せるようにする

`downloadable` から `POST` を受け付け、`composing` へ戻れるようにする。
X の画面構成の変化で一度失敗しても、録り直さずに投稿を試し直せる。

**`downloadable` → `ATTACHED` を拒む既存のガードは残す。** あれは
「`x/failed` が二度届いて `downloadable` に落ちた後、遅れて `x/attached` が
届く」経路を塞ぐためのもので、ここで追加する `POST` とは別の話。

## 3. 自動保存

### 3.1 いつ・どこで

録画が終わって Blob が確定した時点で、**content script が保存する**。
投稿の成否に関わらずファイルは残る。

service worker では保存できない。MV3 の service worker は
`URL.createObjectURL` を持たないため Blob を指す URL を作れない。
content script なら DOM があるので、アンカー要素の `download` 属性で保存できる。

### 3.2 置き場所とファイル名

```
置き場所    ブラウザの既定ダウンロード先 (設定していなければ ~/Downloads)
ファイル名  yt-clip-<videoId>-<開始秒>s.mp4  (X へ添付するものと同じ)
```

**任意の絶対パスは指定できない。** 拡張からはブラウザの設定に従うのみで、
`~/Downloads/yt-clip/` のようなサブフォルダを作るには offscreen document を
戻す必要がある。今回は平置きにする。

**取り直すたびに保存する。** 同じ動画から何本も作れば、その数だけファイルが
残る。「自動で保存する」という要望をそのまま満たす挙動であり、消すかどうかは
利用者に委ねる。

### 3.3 失敗したときの扱い

保存に失敗しても**録画は捨てない**。録画は実時間のコストを払い終えており、
保存は後処理に過ぎない。理由をログに残して投稿の流れは続ける。

## 4. 操作をページ内へ

### 4.1 どこに何を置くか

```
ページ内バー  IN / OUT / 範囲を見る
              録画 / X に投稿 / 再投稿 / 取り直し / 再試行
              状態の文言 (録画中の残り秒数を含む)
popup         状態の文言のみ。ボタンは置かない
```

popup を消さないのは、**YouTube 以外のタブにいるときに状態を見る場所が
無くなる**ため。X の投稿画面で添付に失敗した場面が実際にこれに当たる。

### 4.2 外すもの: 録画済みクリップのプレビュー再生

現在 popup が持っている `<video>` によるプレビューは**移さずに外す**。

- 拡張の IndexedDB は拡張オリジンにあり、**content script (youtube.com
  オリジン) からは読めない**。ページ内で再生するには数 MB を毎回送り直すか、
  録画時の Blob を content script に保持し続けるかになる
- 自動保存 (§3) でファイルは必ず手元にあり、添付が通れば X の画面でも再生できる

要望に含まれていない機能のために転送か常駐を増やす理由が無いため外す。

### 4.3 状態と操作の対応

| 状態 | ページ内バーに出る操作 |
|------|------------------------|
| `idle` | IN |
| `ready` | IN / OUT / 範囲を見る / 録画 |
| `seeking` `recording` `encoding` | なし (状態の文言のみ) |
| `preview` | X に投稿 / 取り直し |
| `composing` | 取り直し |
| `posted` | 再投稿 / 取り直し / IN / OUT / 範囲を見る |
| `downloadable` | 投稿をやり直す / 取り直し |
| `failed` | 再試行 |

`posted` と `ready` では拡大バーを操作できる。それ以外では操作を受け付けない。

## 5. 見た目

### 5.1 方向: YouTube に馴染ませる

YouTube の CSS 変数と Roboto を使い、ダーク / ライトに自動で追従させる。
拡張の異物ではなく YouTube の機能に見えることを狙う。

**YouTube 側がデザインを変えると浮く**という弱点は受け入れる。変数が
無くなった場合に備え、すべての色にフォールバック値を書く (既存コードと同じ方針)。

### 5.2 レイアウト

```
12:19  ▐━━━━━━━━━━━━━━━━▌  13:04
       ↑IN      ●現在    OUT↑

( ● 録画 ) ( ▶ 範囲を見る )        0:15
```

- 1 行目: 拡大バー。左右に窓の開始・終了時刻
- 2 行目: 操作ボタンと状態の文言。右端に範囲の長さ
- ボタンはピル形。主操作 (録画 / 投稿) は塗り、副操作は輪郭のみ

### 5.3 拡大バーに足すもの

- **現在の再生位置マーカー** — いまどこを見ているかが分かる
- **ハンドルの掴み代** — 現在は幅 12px。掴みやすさのため当たり判定を広げる
  (見た目は変えず、透明な余白で広げる)
- 選択範囲の外側を暗くする

## 7. テスト方針

- **状態機械** — `posted` の全遷移、`downloadable` + `POST`。純粋関数なので
  網羅して書く
- **自動保存** — アンカー要素の組み立てとファイル名。DOM 操作を差し替え可能に
  して検証する。保存に失敗しても投稿の流れが続くことも固める
- **ページ内の操作** — 状態ごとに出るボタンが §4.3 の表と一致すること
- **拡大バー** — 現在位置マーカーの位置計算。既存の純粋関数のテストに足す
- **見た目** — 単体テストでは検証しない。`docs/manual-check.md` に
  ダーク / ライト両方での視認性の項目を足す

## 8. この設計で解決しないこと

- **サブフォルダへの保存** — offscreen document を戻す必要があるため見送る
- **保存したファイルの整理** — 増え続けるファイルの掃除は利用者に委ねる
- **ページ内でのクリップ再生** — §4.2 の理由で外す
- **`ready` の「やり直し」ボタン** — popup にあった `RESET_MARKS` の操作は
  ページ内には作らない。バーが常に出ているので、IN を押し直せば同じことが
  できる。状態機械のイベント自体は残す
