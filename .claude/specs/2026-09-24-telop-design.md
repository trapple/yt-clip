# エディットモード (3) テロップ — Phase 1: 手入力

エディットモードで、クリップに**テロップ (字幕の焼き込み)** を入れられるようにする。
文字のサイズ・フォント・ベース色・縁取り色・縁取りの太さを決められる。

**最終目標は、ブラウザ内の Whisper (WebGPU) による自動文字起こし**。この spec
(Phase 1) では手入力だけを作り、Phase 2 の文字起こしがそのまま差し込める
データの形にしておく。

---

## 0. この spec の範囲

| Phase | 中身 | この spec |
|---|---|---|
| 1 | テロップの手入力・スタイル設定・プレビュー・録画への焼き込み | **これ** |
| 2 | WebGPU 上の Whisper で区間の音声を文字起こしし、テロップを自動で埋める | 別 spec (§10 に前提だけ書く) |

Phase 1 だけでも「テロップ入りの切り抜きを X に投稿する」が完成品として成立する。

### 0.1 エディットモード spec との関係 (前提の変更が 3 つある)

`2026-09-23-edit-mode-segments-design.md` §0 はテロップをサブプロジェクト 3 とし、
§0.1 で次の 2 つを前提にしていた。**この spec はどちらも覆す。** また §0 の表が中身に
挙げていた「自由配置」も採らず、下中央固定にする (§3.1。依頼が挙げた設定項目に位置が無いため)。

1. **「テロップは書き出しパイプライン (WebCodecs, サブプロジェクト 2) の上にしか乗らない」**
   → 乗せない。今のリアルタイム録画のまま、`<video>` を canvas に描いて文字を重ね、
   その canvas を録る (§4)。録画はもともと実時間で再生しながら行うので、フレームごとに
   描き足すだけで済み、decode / encode / mux を自前で持つ必要がない。
   サブプロジェクト 2 は不要になるわけではないが (倍速書き出しなど)、テロップの
   前提からは外れる
2. **「テロップの時刻は出力タイムライン (結合後の先頭を 0 とした秒) で持つ」**
   → 元動画の秒で持つ (§2.1)。

2 の理由:

- **区間を触るとテロップが中身からずれる。** 出力の秒で持つと、1 つ目の区間を
  1 秒縮めただけで、後ろのテロップがすべて 1 秒早く出る。区間は拾った順のまま
  並べ替え・削除・伸縮が自由 (エディット spec §2.3) なので、ずれは日常的に起きる
- **テロップが指しているのは「その瞬間に話されていること」で、それは元動画の時刻に
  付いている。** 元動画の秒で持てば、区間をどう組み替えてもテロップは発話に付いてくる
- **Phase 2 の Whisper は元動画の音声を起こすので、返ってくる時刻は元動画の秒になる。**
  変換せずにそのまま入れられる
- **描画側も単純になる。** 録画中も再生中も `video.currentTime` が元動画の秒なので、
  「今出すテロップ」はそれだけで決まる

代償として、**同じ場面を 2 回使うと (重なる区間) テロップも 2 回出る**。発話が 2 回
流れるのだから、字幕が 2 回出るのは自然であり、問題にはしない。

`shared/timeline.ts` の `toSourceTime` はこの前提のために置かれていた。使い道が
無くなるので、`tests/shared/timeline.test.ts` の該当テストごと**削除する**
(使われない関数が「将来こう使う」という誤った設計意図を語り続けるのを避ける)。
エディット spec §0.1 / §2.2 には「テロップ spec で覆した」旨を 1 行書き足す。

---

## 1. できること (Phase 1)

- エディットモードで、テロップを**作る・文言を書く・出す時間を決める・消す**
- テロップの見た目 (5 項目) を ⚙ で決める。**全テロップ共通**
- 再生中、YouTube のプレイヤーの上に**録画と同じ見た目で**テロップが重なって見える
- 録画すると、テロップが焼き込まれたクリップができる

シンプルモードには出さない (依頼が「Edit モードに」であるため)。

## 2. データモデル

### 2.1 テロップ

```typescript
/** 動画に重ねる文字。時刻は元動画の秒 (出力タイムラインではない。spec §0.1) */
export type Telop = {
  startSec: number;
  endSec: number;
  /** 改行を含んでよい。空文字は「まだ書いていない」テロップで、描かない */
  text: string;
};
```

- 検証は区間と同じ規則 (`startSec >= 0`、`endSec > startSec`、有限値)。不正な値は
  UI のバグなので throw する (握り潰さない。エディット spec の `assertValidRange` と同じ方針)
- **ID は振らない。** 区間と同じく、作った順のまま持ち並べ替えないので index が動かない
- **どの区間にも入らないテロップも持てる。** 区間の外なので録画には出ない。一覧で
  「区間外」と示す (§5.2)。区間を後から伸ばせば出るようになるので、消さない

### 2.2 状態に `telops` を足す

`segments` を持つ全ての `ClipState` に、同じ階層で `telops: Telop[]` を足す
(エディット spec §0.1 で予告していた形)。

- **テロップを変えるとクリップは外れる** (`posted` → `ready`)。
  焼き込まれているので、古いクリップを持ち続けると画面と投稿内容が食い違う。
  区間の編集 (`isEditEvent`) と同じく **`ready` と `posted` でだけ受ける**。`preview` と
  `degraded` では区間も触れない (`youtube.ts` の `rangeEditable`) ので、テロップだけ
  触れる非対称を作らない。`RETAKE` で `ready` に戻してから触る
- **区間がすべて消えて `idle` に戻ったら、テロップも消える。** `idle` は何も持たない。
  ただし手入力の文言を ✕ 1 回で失わないよう、**テロップが残っている間は最後の
  1 区間を消させない** (§5.1)。状態機械の規則はそのままで、UI 側で止める
- **区間を作り直したらテロップも消える。** `ADD_SEGMENT` が別の動画の区間で
  作り直すとき (`state.ts` の videoId 比較) に `telops` も `[]` にする。残すと、B の
  動画に A の秒で書いたテロップが付く。`MARK_IN` (シンプルモードの、区間を丸ごと
  置き換える操作) も常に `[]` にする
- **モードを変えるとテロップも消える** (区間と同じ。エディット spec §1.2)
- `failed` からの `RETRY` で `ready` に戻るときは、区間と一緒にテロップも引き継ぐ
- 録画中 (`BUSY_KINDS`) はテロップの編集を受け付けない
- 将来テロップごとにスタイルを上書きしたくなったら、`Telop` に省略可能な項目を
  足せば済む形にしてある (Phase 1 では足さない)

### 2.3 イベント

```typescript
  /** テロップを 1 つ足す。末尾に付く */
  | { type: "ADD_TELOP"; telop: Telop }
  /** 指したテロップを丸ごと差し替える。取りこぼしでずれないよう常に全項目を送る */
  | { type: "UPDATE_TELOP"; index: number; telop: Telop }
  | { type: "REMOVE_TELOP"; index: number }
```

`ready` / `posted` で受ける (§2.2)。`idle` では受けない (区間が無いのにテロップだけ
ある状態は作らない)。

`ClipState` を組み立てる箇所は `reduce` に 20 近くあり、全遷移で `telops` を運ぶ変更になる。
**`segmentsOf` に並ぶ `telopsOf` と、状態を組み立てるヘルパを先に入れてから**遷移を直す
(漏れを防ぐ。plan の順序)。`sw.ts` の `loadSnapshot` は型検査なしで復元するので、
`telops` が欠けた古いスナップショットには `[]` を補う。

Phase 2 の文字起こしは数十件を一度に入れるので、一括投入のイベント (`SET_TELOPS` 相当) は
Phase 2 で足す (Phase 1 では要らない)。

### 2.4 クリップの保存

`StoredClip` には `telops` を**持たせない**。焼き込み済みの Blob なので、録り直しに
使うのは状態側の `telops` であり、保存レコードから読む者がいない。

### 2.5 スタイル (設定)

```typescript
export type Settings = {
  // …既存…
  /** 文字の大きさ。**動画の高さ 1080 px を基準にした px**。実際は高さに比例させる */
  telopFontSizePx: number;     // 既定 64
  /** フォント。プリセットの表示名か、font-family に渡す名前 (§3.2) */
  telopFont: string;           // 既定 "ゴシック"
  /** 文字の色 (#rrggbb) */
  telopFillColor: string;      // 既定 "#ffffff"
  /** 縁取りの色 (#rrggbb) */
  telopStrokeColor: string;    // 既定 "#000000"
  /** 縁取りの太さ。文字の大きさと同じく 1080 px 基準。0 で縁取りなし */
  telopStrokeWidthPx: number;  // 既定 8
};

/**
 * 描画側が受け取る形。設定から組み立てる (`telopStyleOf(settings)`)。
 * `mergeSettings` を通った `Settings` だけを受ける純粋関数として `shared/` に置く
 * (プレビューと録画開始の両方が呼ぶ)。`ctx.font` の読み戻し検証は描画側 (`content/`) で行う
 */
export type TelopStyle = {
  fontSizePx: number;
  fontFamily: string;          // プリセットは展開済みの font-family
  fillColor: string;
  strokeColor: string;
  strokeWidthPx: number;
};
```

- **`Settings` には 5 つの平坦なキーで持つ。** 1 つのオブジェクト (`telopStyle`) に
  まとめると、設定パネルの保存が壊れる。パネルは項目ごとの `fromText` の結果を
  `{ ...patch, ...converted.patch }` と**浅く**重ね、`saveSettings` も
  `{ ...current, ...patch }` で浅く重ねる (`settings-panel.ts` / `settings.ts`)。
  5 項目がそれぞれ `telopStyle` を丸ごと返すと、後の項目が前の項目の変更を黙って
  上書きする。平坦にすれば「`Settings` に 1 行、`SETTINGS_FIELDS` に 1 要素」の作法にも合う

- **設定に置き、全テロップで共通にする。** テロップごとに見た目を変える要望は依頼に無い。
  設定に置けば、動画をまたいで同じ見た目を使い回せる
- **大きさは 1080 px 基準で持ち、動画の高さに比例させる。** 絶対 px で持つと、360p で
  録ったクリップと 1080p で録ったクリップで見た目の大きさが 3 倍違う。プレビュー
  (画面上のプレイヤーの大きさ) と録画 (動画の実解像度) でも大きさが食い違う
- 値の範囲: 文字の大きさ 16〜200、縁取りの太さ 0〜40。**設定パネルでの入力は、範囲外を
  `ok: false` で弾く** (`parseMaxClipSec` と同じ)。読み込み時の範囲外・型違いは既存の
  `mergeSettings` と同じく**既定値に倒して `console.warn` を残す**
- 色は `#rrggbb` だけを受け付ける (`input type="color"` が返す形)

## 3. 描画

### 3.1 描画関数を 1 つにする (`content/telop-render.ts`)

```typescript
export function drawTelops(
  ctx: CanvasRenderingContext2D,
  telops: Telop[],
  sourceSec: number,
  style: TelopStyle,
  width: number,
  height: number,
): void;
```

**プレビューも録画もこの関数で描く。** 画面では CSS (`-webkit-text-stroke` など)、
録画では canvas、と別の手段で描くと、縁取りの付き方や行間が微妙に違い、
「プレビューで見たものと違う」クリップができる。

- `sourceSec` の時点で `startSec <= sourceSec < endSec` のテロップを描く
  (判定は純粋関数 `activeTelops` に切り出してテストする)
- 位置は**画面下の中央に固定**。下端から高さの 8% 空ける。自由配置は作らない
  (依頼に無く、UI が大きく増える)
- **複数が同時に出るときは、作った順に下から積む。** 重ねて描くと読めない
- 改行 (`\n`) で行を分ける。行間はフォントサイズの 1.2 倍
- **自動折り返しはしない。** 幅からはみ出した分は切れる。はみ出しの判定と折り返しは
  日本語の禁則まで含めると重く、Phase 1 では手で改行してもらう (README の制約に書く)
- 縁取りは `strokeText` を先に、`fillText` を後に描く (文字の内側が縁に食われない)。
  `lineWidth = strokeWidthPx × 2 × 倍率` (線は輪郭の両側に乗るので 2 倍)、
  `lineJoin = "round"` (角がトゲにならない)。太さ 0 なら `strokeText` を呼ばない
- 文字は太字 (700) 固定。テロップとして読める太さが要り、細字を選ぶ要望も無い

### 3.2 フォントの選択肢

**プリセット 3 つから選ぶか、手元にあるフォントの名前を書く。** 入力欄は候補付きの
テキスト欄 (`<input list>` + `<datalist>`) にする。

| プリセット (表示名) | 展開する font-family |
|---|---|
| ゴシック | `"Hiragino Sans", "Hiragino Kaku Gothic ProN", "Yu Gothic", "Meiryo", sans-serif` |
| 明朝 | `"Hiragino Mincho ProN", "Yu Mincho", serif` |
| 丸ゴシック | `"Hiragino Maru Gothic ProN", "BIZ UDGothic", sans-serif` |

- プリセットの表示名と一致すればその font-family に展開する。それ以外の文字列は
  フォント名とみなし、`"<名前>", sans-serif` にする (無ければゴシック系に落ちる)
- **名前で指定するだけなら権限は要らない。** Local Font Access の権限が要るのは
  インストール済みフォントを**列挙**するときだけ。列挙はしない (候補に出せるのは
  プリセットだけになるが、審査で説明が要る権限をフォント選びのために増やさない)
- **手元に無いフォントを検出して知らせることはしない。** `document.fonts.check()` は
  登録された Web フォントについてしか答えず、システムフォントには常に `true` を返すので
  判定に使えない。代わりのフォントで描かれたことは、設定を変えた瞬間のプレビュー (§5.4)
  でその場で見える
- 空文字と、`"` `'` `\` `;` を含む名前は `fromText` で `ok: false` にする。引用符が混ざると
  font の指定全体が不正になり、`ctx.font` への代入が**例外を出さずに無視される** (大きさまで
  既定の 10px のまま録画される)
- 念のため、描画側は font 指定が受け付けられたかを確かめ、無視されたらゴシックに倒して
  `console.warn` を残す (設定が手で書き換えられた場合の保険)。**代入した文字列と読み戻しの
  一致では判定しない** (`ctx.font` は `bold` → `700` や引用符の付け直しなど正規化した値を返すので、
  必ず不一致になる)。代入の前に既知の値 (`10px sans-serif`) を入れておき、代入後に**その値から
  変わったか**で見る (不正な指定は無視され、値が変わらない)。判定は録画開始時とプレビューの
  スタイル更新時に 1 回だけ行い、フレームごとには行わない
- `,` はファミリの区切りとして解釈され、候補が 2 つになるだけで壊れないので弾かない
- 保存値はプリセットの表示名のまま持つ。表示名を変えると保存済みの値はフォント名扱いに
  なり、`sans-serif` に落ちるだけで壊れはしない

**Web フォントは同梱しない。** 日本語フォントは 1 書体で数 MB あり、拡張の
サイズが一桁増える。環境によって字形が変わること、手元に無いフォント名を書くと
代わりのフォントで描かれることは README の制約に書く。

`SettingsField.control` の `{ kind: "text" }` に、省略可能な `suggestions` を足す
(パネルは値があれば `datalist` を付ける)。

## 4. 録画

### 4.1 テロップがあるときだけ canvas を経由する

```
テロップなし: video.captureStream() ─────────────────→ MediaRecorder   (今と同じ)
テロップあり: video ─drawImage─→ canvas ─drawTelops─→ canvas.captureStream(0)
              video.captureStream() の音声 ─────────────┘→ MediaRecorder
```

**どの区間にも重なる空でないテロップが 1 つも無いなら、今の経路をそのまま使う。**
(判定は §5.2 の区間外判定と同じ関数で行う。区間外のテロップしか無いときに canvas を挟まない)
canvas を挟むと描画の負荷とフレーム落ちの可能性が増えるので、要らないときに払わない。
シンプルモードの録画は一切変わらない。

`recorder.ts` の `startRecording` に「映像トラックの差し替え」を受ける口を足す形にし、
canvas 側は別モジュール (`content/telop-compositor.ts`) に置く。映像トラックを組んでいるのは
`buildRecordingStream` (`[...captured.getVideoTracks(), downmixed]`) なので、差し替えはここで行う。
**`Compositor.release()` は `buildRecordingStream` が返す `release` に繋ぐ。** `release` は
`recorder.onstop` から呼ばれ、録画が自動で止まった経路でも走る。繋がないと、自動停止の
ときに rVFC のループと canvas のトラックが残る。

```typescript
export type Compositor = {
  /** 合成済みの映像トラック */
  track: MediaStreamTrack;
  /** 描画ループを止め、トラックを止める。二度呼ばれても安全 */
  release(): void;
};

export function startCompositor(
  video: HTMLVideoElement,
  telops: Telop[],
  style: TelopStyle,
): Compositor;
```

### 4.2 フレームは動画のフレームに合わせて出す

- `canvas.captureStream(0)` (自動では出さない) にし、`requestVideoFrameCallback` で
  **動画の新しいフレームが来るたびに**描いて `track.requestFrame()` を呼ぶ。
  タイマーで描くと、動画と canvas のフレームがずれて同じ絵が 2 回出たり飛んだりする
- 描くときの `sourceSec` には rVFC が渡す `metadata.mediaTime` を使う。
  `video.currentTime` は描画時点ではすでに先へ進んでいることがある
- canvas の大きさは**録画開始時の `videoWidth` / `videoHeight` で固定**する。録画中に
  YouTube が画質を切り替えても canvas の大きさは変えず、`drawImage` で引き伸ばす
  (MediaRecorder は途中で解像度が変わるのを想定していない)
- pause / resume (区間の間のシーク) は今と同じく MediaRecorder に対して行う。
  canvas は描き続けてよい (pause 中のフレームは記録されない)

### 4.3 録画中にタブが隠れたら中断する (§9-4 の結果次第)

rVFC は描画の工程で走るので、**非表示のタブでは発火しない**。`canvas.captureStream()` も
非表示タブではフレームを出さなくなるという報告がある。そうなると、映像が最後のフレームで
止まり音声だけ進むクリップができる。今の経路 (`video.captureStream()`) はメディアの
パイプラインから直接取るので、映像は止まらない**はず**だが、これも確かめていない (また OUT の検知 `onReachTime` も rVFC
なので、非表示の間は録画が OUT を過ぎて伸びる可能性がある。§9-4 でテロップなしも 1 回試し、
伸びるなら既存の問題として別に扱う。この spec のスコープ外)。

§9-4 で実際に止まると分かった場合:

- 録画中に `visibilitychange` で `document.hidden` になったら、**録画を中断して**
  失敗理由 `telop-tab-hidden` (「テロップ付きの録画中はタブを表示したままにしてください」) を出す
- 録画を始める前 (`prepareRecording`。DRM の検査と同じ場所) で `document.hidden` なら、同じ理由で
  始めない。**`beginRecording` では止めない。** そこの失敗経路は `recorder/failed` で、router が
  理由を問わず `recording-aborted` に落とすため、専用の文言が出ない。そのため §4.1 の
  「テロップ付きの経路か」の判定も `prepareRecording` で先に済ませる
- 録画中に隠れたときは、区間の間の広告検査と同じく `send({ type: "FAIL", reason })` で落とす
  (監視は compositor の開始から)
- `visibilitychange` の監視は `Compositor.release()` で外す (録画が終わった後に `FAIL` を送らない)
- 続行して警告だけ出す案は採らない。壊れたクリップを作ってから気付かせることになる
  (広告が挟まったときに中断するのと同じ考え方)
- README の制約に「テロップ付きの録画中はタブを離れられない」と書く

止まらないと分かった場合は、この節ごと実装しない。

**テロップなしの経路も止まると分かった場合** (§9-4 の対照): 中断はテロップ限定ではなく
録画全体の規則にし、理由名から `telop-` を外す (`tab-hidden`)。README の制約も
「録画中はタブを離れられない」に一般化する。

### 4.4 録画するテロップと設定は録画開始時に固定する

録画中に ⚙ でスタイルを変えても、その録画には効かない。途中で見た目が変わる
クリップを作らない。

## 5. UI

### 5.1 テロップの一覧 (`content/telop-list.ts`)

区間の一覧 (`segment-list.ts`) の下に置く。エディットモードで、区間が 1 つ以上あるときだけ出す。

```
テロップ                                       [＋ テロップ]
┌────────────────────────────────────────────────────┐
│ 1. 0:12.3 〜 0:15.3  [開始を今に][終了を今に] ▶ ✕ │
│ ┌──────────────────────────────────────────────┐ │
│ │ こんにちは                                   │ │
│ └──────────────────────────────────────────────┘ │
│ 2. 0:40.0 〜 0:43.0 (区間外) …                    │
└────────────────────────────────────────────────────┘
```

- **＋ テロップ** — 今の再生位置から 3 秒のテロップを文言なしで足す。動画の長さを
  超えるなら終わりを動画の終わりに詰める
- **開始を今に / 終了を今に** — 今の再生位置に合わせる。開始が終了以上になる操作は
  押しても送らず、バーのステータスに理由を出す (黙って無反応にしない)
- **▶** — そのテロップの開始から再生する
- **✕** — 消す
- **区間の一覧で最後の 1 区間の ✕ を押したとき、テロップが残っていれば消さない。**
  バーのステータスに「テロップが N 件残っています。先にテロップを消してください」と
  出す (§2.2。手入力の文言を ✕ 1 回で失わせない)。`segment-list.ts` は押されたことを
  伝えるだけなので、判定は `youtube.ts` の削除処理に置く。手元の写しが古くて止め損ねた
  場合に備え、区間の削除の後の状態通知でテロップが空になっていたら「テロップも消えました」と
  ステータスに出す (黙って消さない)
- **文言** — 複数行の入力欄。`change` (フォーカスが外れたとき) で `UPDATE_TELOP` を送る。
  1 文字ごとに送ると、そのたびにクリップが外れて状態通知が飛ぶ
- 同じテロップを別の経路 (別タブの popup など) で同時に書き換えた場合は、後に確定した方が勝つ。
  Phase 1 ではそれでよい
- **一覧を描き直しても、フォーカス中の入力欄は要素も `value` も触らない。** 状態通知で
  一覧を作り直したり `value` を差し替えたりすると、打ちかけの文字が消える。しかも
  プログラムから `value` を書くと、その後 blur しても `change` が発火しないので、消えたことにも
  気付けない。時刻のラベルなど表示だけを更新し、入力欄は blur の `change` で状態が追いつくのを待つ
- 一覧を操作できるのは `ready` / `posted` のときだけ (区間の拡大バーと同じ `rangeEditable`)
- 時刻の細かい調整 (ドラッグ) は作らない。拡大バーは区間専用のまま (エディット spec §5.1)
- **一覧は選択状態を持たない。** 区間の一覧と違い、拡大バーと連動させないため

YouTube のショートカット (スペースで再生、`f` で全画面など) は input / textarea の中では
効かない作りになっており、既存の設定パネルも伝播を止めていない。テロップの入力欄は
**念のため** `keydown` の伝播を止める (打つ文字が多く、YouTube 側の判定が変わったときの
被害が大きいため)。

### 5.2 区間外の表示

どの区間にも一部でも重ならないテロップは、時刻の横に「(区間外)」と出す。
**消しも止めもしない。** 録画には出ないことが分かれば十分。

### 5.3 プレイヤー上のプレビュー

エディットモードでテロップが 1 つ以上あるとき、`<video>` の上にぴったり重なる
canvas を置き、`requestVideoFrameCallback` ごとに `drawTelops` で描く (§3.1)。

- **rVFC は再生中しか発火しない。** 手入力は「止めて文言を打つ」が主なので、それだけでは
  止めている間にテロップを直してもプレビューが変わらない。次のときにも
  `video.currentTime` で 1 回描き直す: 状態の `telops` が変わったとき、`seeked`、
  設定が変わったとき、表示サイズが変わったとき
- `pointer-events: none`。プレイヤーの操作を塞がない
- 大きさは `<video>` の表示サイズに合わせる (`ResizeObserver`)。テロップの倍率は
  表示の高さ ÷ 1080 になるので、画面上でも録画と同じ比率で見える
- **canvas は `<video>` と同じ親要素に入れ、`<video>` の `left` / `top` / `width` / `height` に
  追従させる。** YouTube は `video.html5-main-video` に inline のスタイルで位置と大きさを当てて、
  動画のアスペクト比ぴったりに置いている。レターボックスは `<video>` の外側にできるので、
  `<video>` の矩形に合わせれば、黒帯の上にテロップが乗ることはない。`ResizeObserver` は
  大きさの変化しか拾わないので、そのたびに位置も読み直す (シアターモードや全画面では、
  大きさと位置がほぼ同時に変わる)
- 別の動画を見ているとき・シンプルモードでは出さない

### 5.4 設定パネル

⚙ に「テロップ」の 5 項目を足す。**モードに関わらず常に出し**、ヒントに
「エディットモードのテロップに使う」と書く。パネルには項目をモードで出し分ける
仕組みが無く (分岐は `scope` だけ)、しかもモード自体が同じパネルの未保存の選択肢
なので、出し分けると「モードを選び直した瞬間に項目が出入りする」処理まで要る。
見えていて困る項目ではないので、その仕組みは足さない。

| 項目 | キー | 入力 |
|---|---|---|
| 文字サイズ | `telopFontSizePx` | 数値 (テキスト欄。既存の最大長と同じ作法) |
| フォント | `telopFont` | 候補付きテキスト (§3.2) |
| 文字の色 | `telopFillColor` | 色 |
| 縁取りの色 | `telopStrokeColor` | 色 |
| 縁取りの太さ | `telopStrokeWidthPx` | 数値 |

`SettingsField.control` に `{ kind: "color" }` を足す。パネルはこれを見て
`input type="color"` を作る。`toText` / `fromText` は `#rrggbb` の文字列で往復する。
項目ごとに別のキーなので、保存時の浅いマージで互いを消さない (§2.5)。

設定を変えたらプレビューは即座に描き直す。

## 6. エラー

| 状況 | 扱い |
|---|---|
| canvas に映像が描けない (汚染・`SecurityError`) | 録画を始める前 (`prepareRecording`。理由を `FAIL` で出せる場所。§4.3 と同じ理由) に 1 フレーム描いて `getImageData` で確かめ、失敗したら失敗理由 `telop-render-failed` (「テロップを動画に描けませんでした」) で `FAIL`。**テロップなしで録って続行しない** (実時間を払った後で「テロップが入っていない」と気付くことになる)。`internal-error` に寄せない: `applyStateToDisplay` は `failed` を受けると `FAILURE_MESSAGES` の文言でステータスを上書きするので、先に出した理由が「内部エラー」に消される。`types.ts` の「理由と文言は必ず対で足す」に従う |
| rVFC が使えない環境 | 同上。Chrome 83 以降にあるので、実質起きない |
| テロップ付きの録画中にタブが隠れた | §4.3 (§9-4 で止まると分かった場合だけ)。文言は「…録り直してください」まで含める。`failed` → `RETRY` で区間もテロップも残る (§2.2) ので、中断で作業は消えない |
| プレビューが描けない | `console.warn` だけ残して続行。プレビューは目安であり、録画を止める理由にならない (範囲の帯と同じ扱い) |
| 状態に不正なテロップが来た | `reduce` で検証して throw → `internal-error` (区間と同じ) |

## 7. テスト

### 7.1 単体 (`vitest`)

- `activeTelops`: 境界 (`startSec` ちょうどは出す、`endSec` ちょうどは出さない)、
  空文字を除く、作った順を保つ
- テロップのレイアウト計算 (行の分割、下から積む位置、倍率) を純粋関数にしてテストする。
  canvas 自体は jsdom で描けないので、`ctx` はモックにして呼び出し順 (stroke → fill) と
  `lineWidth` を確かめる
- `reduce`: `ADD_TELOP` / `UPDATE_TELOP` / `REMOVE_TELOP` の各状態での受け方
  (`preview` / `degraded` / `idle` では受けない)、クリップが外れること、不正な index・不正な時刻で
  `internal-error`、`idle` に戻るとテロップも消えること、別の動画で作り直すと消えること、
  `failed` → `RETRY` で引き継ぐこと、モード変更で消えること
- `mergeSettings`: テロップの 5 キーの欠落・型違い・範囲外・不正な色が既定値に倒れること
- 設定パネル: テロップの 2 項目を同時に変えて保存しても、両方が保存されること
- テロップ一覧: 再描画でフォーカス中の入力欄の要素も `value` も変わらないこと
- 録画: テロップの有無で経路が分かれること、自動停止でも compositor が解放されること
- フォント名の展開 (プリセット / 任意の名前)、引用符などを含む名前を `fromText` が弾くこと
- 描画側 (`content/`、jsdom の `ctx` モック): 番兵のまま → ゴシックに倒れ `console.warn` が残る、
  変わっていれば採用、の 2 ケース。フォント名の展開は `shared/` の `telopStyleOf` に対して別に書く
- `prepareRecording`: テロップ付きで `document.hidden` なら専用の理由で `FAIL` すること
- 区間外の判定
- `youtube.ts` (jsdom): テロップが残っているときに最後の区間の ✕ が止まること、
  テロップ一覧の入力欄で YouTube のショートカットに伝播しないこと

### 7.2 E2E (`playwright`)

**足さない。** エディット spec §7.2 と同じ判断で、UI の振る舞いは
`tests/content/youtube.test.ts` の jsdom テストで固定できる。録画・焼き込みの確認は手動 (§8)。

## 8. 手動確認 (`docs/manual-check.md` に足す)

- テロップ付きで 2 区間を録り、**出力の長さが区間の合計と一致し、音ズレが無い**
- 焼き込まれたテロップの位置・大きさ・色・縁取りが、プレビューと同じに見える
- 360p と 1080p で録って、テロップの見た目の比率が同じ
- 録画中に画質が変わっても、出力の解像度が変わらず映像が崩れない
- テロップなしの録画が今までと変わらない (canvas を経由していない)
- 入力欄で文字を打っても YouTube のショートカットが発火しない
- 1080p60 で録ってフレーム落ち (カクつき) が目立たない
- テロップ付きの録画中にウィンドウを最小化した場合も、別のタブへ移った場合と同じに扱われる
- テロップ付きの録画中に別のタブへ移ると、壊れたクリップを作らずに理由付きで中断する (§4.3 を実装した場合)

## 9. 未検証の前提とフォールバック

**実装の最初のタスクをこの検証にする。** §1〜§3・§5 の多くはこれに依存しないが、
§4 はこれが崩れると成立しない。

1. **YouTube の `<video>` を canvas に描いても汚染されないか。** ほぼ確定している:
   `captureStream()` はオリジンの違うメディアでは無音・黒のトラックしか返さないので、今の
   録画が動いている時点で同一オリジン扱いと分かる。`drawImage` も同じ判定を使う
2. **`canvas.captureStream(0)` + `requestFrame()` の映像を MediaRecorder (MP4) で録り、
   pause / resume をまたいでも長さと音声の同期が保たれるか。** エディット spec §9.1 で
   確かめたのは `video.captureStream()` の場合だけ
3. **1080p60 で毎フレーム `drawImage` + テロップ描画をしてもフレームを落とさないか**
4. **タブが隠れている間も canvas 経由のフレームが出続けるか。** rVFC は非表示タブでは
   発火せず、`canvas.captureStream()` も止まるという報告がある。**崩れる見込みが高い**

検証:

- 2 区間 × 各 3 秒を、固定文言のテロップ付きで 1080p で録り、出力が 6 秒前後で
  音ズレが無く、テロップが入っていることを確かめる (1〜3)
- 10 秒の区間を録り、途中で 5 秒ほど別のタブへ移る。出力の映像が止まっていないかを
  確かめる (4)。テロップなしでも 1 回行い、OUT を過ぎて伸びないかも見る (§4.3 の注)

フォールバック:

- 1 が崩れた場合: 描いた映像を録れないので、**Phase 1 は成立しない**。テロップは
  サブプロジェクト 2 (WebCodecs で decode したフレームなら汚染されない) の上に
  乗せる元の計画へ戻る
- 2 が崩れた場合: 区間ごとに canvas の描画自体を止めてトラックを無音・静止にするなど、
  pause の掛け方を変えて再検証する。それでも駄目なら 1 と同じく元の計画へ戻る
- 3 が崩れた場合: 第一手として、テロップの層は出すテロップが変わったときだけ別の
  canvas に描き直し、毎フレームは `drawImage` を 2 回だけにする。それでも落ちるなら、
  60fps の動画は canvas を 30fps で出す (rVFC を 1 回おきにする)。画質の制約として README に書く
- 4 が崩れた場合: §4.3 のとおり、タブが隠れたら中断する。隠れている間だけタイマーで描く案は、
  canvas のキャプチャ自体が止まる報告があるので、検証なしには採らない

## 10. Phase 2 (自動文字起こし) に向けて決めておくこと

Phase 2 は別 spec にする。Phase 1 で先に決めておくのは次の 2 つだけ。

- **文字起こしの出力は `Telop[]` (元動画の秒) にする。** 区間ごとの音声を起こし、
  得られたセグメントをそのまま `ADD_TELOP` で入れる。Phase 1 の UI で手直しできる
- **テロップの持ち方にスタイルや話者を足さない。** Whisper が返すのは時刻と文言だけで、
  Phase 1 の `Telop` と一致する

Phase 2 の spec で扱うことが分かっている論点 (ここでは決めない):

- モデルの置き場所。数十〜数百 MB あり拡張に同梱できないので、初回にダウンロードして
  キャッシュする。**取得先のホスト権限とプライバシーポリシーの改定が要る**
  (音声は外に出ないが、モデルの取得で外部に通信する)
- MV3 の CSP で wasm / WebGPU を動かせるか (`wasm-unsafe-eval`)、どの文脈
  (offscreen document / content script) で推論するか
- 区間の音声をどう取り出すか (録画とは別に、実時間で再生しながら取るのか)

## 仮定と根拠

- テロップは焼き込み (動画の映像に描き込む) — 根拠: 出力は X に投稿する MP4 で、
  X は字幕トラックを読まない (README「投稿本文」「録画」)。焼き込み以外に見せる道が無い
- シンプルモードには出さない — 根拠: 依頼文「Editモードにテロップ機能を追加したい」
- 位置は下中央固定、自由配置なし — 根拠: 依頼文が挙げた設定項目はサイズ・フォント・
  ベース色・縁取り色・縁取り太さの 5 つだけで、位置は無い
- スタイルは全テロップ共通 — 根拠: 同上。テロップごとに変える要望は無い
- 文字の太さは太字固定 — 根拠: 依頼の 5 項目に含まれない。テロップの慣例
- 自動文字起こしは Phase 2 で WebGPU の Whisper — 根拠: ユーザーの回答「WebGPUつかった
  Whisperを目標としつつ、Phase1では手入力」

## 検討した選択肢

### 焼き込みの方式

- **採用: リアルタイム録画に canvas 合成を差し込む** — 今の録画方式のまま、描き足す
  だけで済む。テロップが無ければ今と同じ経路
- 不採用: WebCodecs の書き出しパイプライン (サブプロジェクト 2) を先に作る — decode /
  encode / mux を自前で持つことになり、テロップの前にもう 1 つ大きな spec が要る。
  canvas 合成が §9 の検証で崩れたときの退路として残す
- 不採用: 録画後に別途焼き込む (ffmpeg.wasm など) — 録画の実時間に加えて変換の時間が
  かかり、wasm の同梱で拡張も重くなる

### 非表示タブで止まらない合成 (§9-4 が崩れたときの候補)

- **Phase 1 では採らず、§9-4 が崩れたときに検討する: `MediaStreamTrackProcessor` /
  `MediaStreamTrackGenerator` (Chrome 94+) で `video.captureStream()` の映像フレームを
  Worker 内の `OffscreenCanvas` で合成する** — 描画の工程 (rVFC・タブの可視性) に依存せず
  フレームが流れてくるので、「タブを離れられない」制約そのものを消せる可能性がある。
  ただし Worker・フレームの寿命管理 (`VideoFrame.close()`)・pause / resume との噛み合わせと
  検証の範囲が大きく増えるため、まずは単純な canvas 合成で §9 を検証し、4 が崩れたら
  中断で出すか、この方式に進むかをその時点で決める

### 時刻の座標系

- **採用: 元動画の秒** (§0.1)
- 不採用: 出力タイムラインの秒 — 区間を触るたびにテロップがずれる。Whisper の出力も
  変換が要る

### プレビュー

- **採用: 同じ描画関数で canvas に描いてプレイヤーに重ねる** — 録画と見た目が一致する
- 不採用: DOM + CSS で描く — 縁取りや行間が録画とずれる

### テロップの時刻の決め方

- **採用: 「開始を今に / 終了を今に」ボタン** — 区間の IN / OUT と同じ操作感で、
  拡大バーを増やさずに済む
- 不採用: テロップ用のタイムラインを作ってドラッグ — UI が 1 つ丸ごと増える。
  Phase 2 で時刻は自動で入るようになるので、手での細かい調整に投資しない
