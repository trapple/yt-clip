# UI の右側パネル化

yt-clip の UI は今、プレイヤー直下 (`#below`) に全部を縦に積んでいる。操作ボタンの行・拡大バー・
区間の一覧・テロップの一覧・設定パネルが順に並ぶ。シンプルモードでは動画と操作が 1 画面に
ぎりぎり収まるが、エディットモードでは区間とテロップが増えるほど下へ伸び、スクロールしないと
操作できない。設定パネルを開いたときも同じことが起きる。

**区間・テロップ・設定を、画面右側に固定したパネル (オーバーレイ) へ移す。** 拡大バーと操作ボタンの行は、
幅が要るのでプレイヤー直下に残す (並びは今のまま: 拡大バー → 操作の行)。

**受け入れ条件 (依頼の核):** 画面 1440x900 のノート PC 相当 (viewport 1440x795) で、エディットモードで
区間 5 つ・テロップ 5 つがあっても、プレイヤー直下のバーの下端が画面内に収まり、スクロールせずに
IN / OUT / 録画と拡大バーを操作できる。区間とテロップの一覧はパネルの中でスクロールして届く。

この spec は `feat/telop-phase1` (テロップ Phase 1。main には未マージ) の UI を前提にする。

---

## 1. 置き場所

```
+--------------------------------+  +--------------+
|                                |  | yt-clip    ▶ |  ← 見出し (折り畳み)
|             動画               |  | 区間         |
|         テロップが見える         |  |  1. 0:10 ... |
|                                |  |  2. 1:20 ... |
+--------------------------------+  | テロップ      |
| |=====[──────────]=====|       |  |  1. ...      |
| [＋区間][IN][OUT] ●録画 状態… ⚙ |  | 設定 (⚙ で)  |
+--------------------------------+  | (中でスクロール)|
                                    +--------------+
```

| 部品 | 置き場所 | 理由 |
|---|---|---|
| 操作ボタンの行 (＋区間 / IN / OUT / ▶ / 録画など / 状態 / ⚙) | プレイヤー直下 (今と同じ) | 動画を見ながら押す。IN / OUT は再生位置と一緒に見たい |
| 拡大バー | プレイヤー直下 (今と同じ) | 幅がそのまま精度になる。パネル幅 (400px) に縮めるとハンドルが粗くなる |
| 区間の一覧 | 右側パネル | 数が増えて下へ伸びる |
| テロップの一覧 | 右側パネル | 同上。入力欄があり背が高い |
| 設定パネル | 右側パネル | 項目が 8 つあり、開くと最も背が伸びる |

**右側パネル:**

- `position: fixed`。画面の右端から 16px、上端は YouTube のヘッダー (56px) の下 12px
- 幅 400px。高さは中身に合わせ、最大で画面の下端から 16px まで。**超えた分はパネルの中だけでスクロールする**
- おすすめ動画の列 (`#secondary`) の上に重なる。YouTube の通常のレイアウトでは、プレイヤーの右側は
  おすすめ動画の列なので、動画は隠れない
- 不透明な背景と影を付ける (下のおすすめ動画が透けると読めない)。**パネルの地の色をパレットに 1 つ足す**
  (`--ytc-panel`: light `#ffffff` / dark `#212121`)。既存の `--ytc-surface` はテロップ行・選択中の区間行・
  設定パネルの背景に使っており、それを地にすると行と設定が地に溶ける。テーマの切り替えにも追従する
- 重なり順 (`z-index`) は 2000。YouTube のヘッダーのメニュー類より下、ページ本体より上
- ヘッダーの高さ (56px)・おすすめ列の幅 (402px 前後)・ヘッダーのメニューの重なり順は実機の値。
  **実装時に DevTools で確かめ、`side-panel.ts` のコメントに出所を書く**
- `document.body` の直下に置く。`#below` の中に置くと、YouTube の再描画でバーと一緒に外れる。
  **`mount()` で、パネルが body から外れていたら付け直す** (バーの有無を見ているのと同じ場所)
- **全画面の間 (`document.fullscreenElement != null`) はパネルを隠す** (`fullscreenchange` で切り替える)。
  `!== null` にしない: jsdom は `fullscreenElement` を持たず `undefined` を返すので、テストで常に全画面扱いになる。
  body 直下の fixed 要素は全画面の動画の上に残りうる。「動画は隠れない」が選んだ理由なので、全画面では出さない

**プレイヤー直下の操作の行:** 状態の文言が長いと (「テロップが N 件残っています…」など) 行が 2 段に折り返し、
バーが伸びて受け入れ条件を食う。**状態の文言は 1 行に収め、はみ出した分は省略記号 (…) にする**。全文は
マウスを乗せると出る (`title`)。`#yt-clip-bar-status` (`span`、flex の子) に
`flex:1; min-width:0; overflow:hidden; text-overflow:ellipsis; white-space:nowrap` を当てる (`min-width:0` が無いと縮まず折り返す)

## 2. いつ出すか

| 状況 | パネル |
|---|---|
| エディットモードで、区間が 1 つ以上ある | 出す (区間・テロップの一覧) |
| ⚙ で設定を開いている (モードに関わらず) | 出す (設定。エディットなら一覧の下) |
| シンプルモードで設定を閉じている | 出さない (中身が無い) |
| エディットモードで区間が 0 個、設定も閉じている | 出さない |
| 動画ページ以外 (SPA でホームへ移ったなど) | 出さない |

- 中身が 1 つも無いときは、パネルごと隠す。空の枠だけを出さない (区間の一覧と同じ方針)
- ⚙ は今どおりプレイヤー直下の行に置き、押すと設定をパネルに開閉する

## 3. 折り畳み

- パネルの見出し (「yt-clip」) に折り畳みボタン (▶ / ◀) を置く。畳むと、見出しの 1 行だけが残る
- シアターモードや狭い画面 (YouTube が 1 列表示に切り替わる幅) では、パネルが動画の右側に重なる。
  そのときは畳んでもらう。**自動では畳まない** (いつ重なるかの判定は YouTube のレイアウトに依存し、
  外れると勝手に消えたように見える)
- 畳んだ状態は、そのタブを開いている間だけ覚える (保存しない)。保存すると「パネルが出ない」
  という相談の原因になりやすく、得るものが小さい
- 設定を開いたとき (⚙) と区間・テロップを足したときは、畳んでいても開く。押した結果が見えないと、無反応に見える
- **開いたうえで、結果をパネルの見える範囲に入れる。** 設定は一覧の下に入るので、区間とテロップが多いと
  ⚙ を押してもパネルの下に隠れる。設定を開いたら設定の先頭へ、区間・テロップを足したら足した行へ、
  パネルの中だけをスクロールする。**`scrollIntoView` は使わない** (ページまで動かして動画の位置がずれうるうえ、
  jsdom に無い)。パネルの本体の `scrollTop` を自前で合わせ、対象の先頭をパネルの上端に揃える
  (対象が既に全部見えていれば動かさない)。計算は `side-panel.ts` の `scrollTo(target)` に置く
- 見出しの折り畳み (▶) は、シアターモードでも見出しの 1 行が動画の右上に残る。README の制約にそう書く

## 4. 作り

- 新しいモジュール `src/content/side-panel.ts`: パネルの枠 (見出し・折り畳み・中身の箱) だけを持つ
  ```typescript
  export type SidePanel = {
    element: HTMLElement;
    /** 中身の箱。区間の一覧・テロップの一覧・設定パネルをこの順に入れる */
    body: HTMLElement;
    /**
     * 出すか隠すか。**理由の計算は youtube.ts の 1 箇所に置く** (中身が無い / 全画面 / 動画ページ以外、の
     * どれかなら隠す)。パネルは理由を知らない
     */
    setVisible(visible: boolean): void;
    /** 畳んでいれば開く (設定を開いた・区間やテロップを足したとき) */
    reveal(): void;
    /** 本体の中だけをスクロールして、target の先頭を見える範囲に入れる */
    scrollTo(target: HTMLElement): void;
    destroy(): void;
  };
  export function createSidePanel(): SidePanel;
  ```
- 区間の一覧 (`segment-list.ts`)・テロップの一覧 (`telop-list.ts`)・設定パネル (`settings-panel.ts`) は
  **中身を変えない**。入れる先を `#yt-clip-bar` からパネルの `body` に変えるだけ
- `youtube.ts` の `buildBar` はプレイヤー直下のバー (操作の行 + 拡大バー) だけを作り、一覧と設定は
  パネルに入れる。バーを作り直す (`applyMode` / `mount`) ときは、パネルの中身も入れ直す
  (古い一覧を残さない)
- パネルを出すかは youtube.ts で決めて `setVisible` に渡す。「中身があるか」は各部品の `hidden` から決める
  (区間の一覧・テロップの一覧・設定パネルの 3 つのうち 1 つでも見えていれば出す)
- テーマの切り替え (`themeObserver`) で、バーと同じくパネルにも `applyPalette` する
- 動画ページ以外へ移ったら (`currentVideoId()` が null)、パネルを隠す
- **別の動画へ SPA 遷移したら、一覧とパネルの表示を今の動画に合わせ直す。** 今は href が変わっても次の状態通知まで
  一覧が前の動画の区間を出したままになる。プレイヤーの下では目立たなかったが、固定のパネルでは動画 B の画面に
  A の区間が出続ける。observer の href の分岐で、区間の写しと同じ規則 (別の動画では空) で一覧を描き直す
- **順序:** 隠れていたパネルは `offsetTop` などが 0 で `scrollTop` も効かないので、必ず
  `setVisible(true)` → `reveal()` → `scrollTo(target)` の順に呼ぶ (シンプルモードで ⚙ を押す経路で効く)
- `scrollTo` の計算は `getBoundingClientRect()` の差で行う (テロップの行は一覧の中の入れ子なので、`offsetTop` だと
  基準の祖先がずれる)
- 区間・テロップを足した行へのスクロールは、クリック時ではなく状態機械の応答を描いた後 (`applyStateToDisplay`) に行う。
  区間の `selectLastOnNextState` と同じ形の「足した直後の 1 回だけ末尾へ」フラグをテロップにも置く
- 状態の文言に `flex:1` を当てると、⚙ の `margin-left:auto` は要らなくなる。消して意図を 1 つにする
- 設定パネルの開閉は `settingsPanel.toggle()` のまま (中身を変えない)。開いたかどうかは `settingsPanel.element.hidden`
  で読む

## 5. テスト

- `side-panel.ts` の単体 (jsdom): `setVisible(false)` で隠れる / 折り畳みで本体が隠れ見出しは残る /
  `reveal` で開く / `destroy` で DOM から外れる
- `youtube.test.ts`: 一覧と設定がパネルに入ること、エディットで区間があるとパネルが出ること、
  シンプルで設定を閉じるとパネルが消えること、⚙ で設定がパネルに開くこと、畳んだ状態で ⚙ を押すと開くこと、
  モードを変えてバーを作り直しても一覧が 2 重にならないこと
- 既存テストのうち、一覧や設定を `#yt-clip-bar` の中から探しているものは、探す場所をパネルに変える。
  **検査そのものは弱めない**
- `youtube.test.ts` の `buildPage()` は各テストで `document.body.innerHTML = ""` にする。`mount()` がパネルを
  付け直すことをテストで固定する (付け直さないと 2 つ目以降のテストでパネルが DOM に無い)
- 全画面の間はパネルが隠れる (`Object.defineProperty(document, "fullscreenElement", …)` で立てて `fullscreenchange` を
  dispatch する) / ⚙ を押すと設定を対象に `scrollTo` が呼ばれる (jsdom はレイアウトを持たないので、`side-panel` の
  `scrollTo` の計算そのものは `offsetTop` / `clientHeight` を stub した単体テストで見る) / 別の動画へ移ると一覧が空になる
- E2E: `e2e/smoke.spec.ts` と `e2e/telop-check.spec.ts` の、一覧・＋ テロップを `#yt-clip-bar` の中から
  探している箇所をパネルに変える。`npm run check:telop` を実機で通し、パネルに入ったテロップの一覧で
  同じ 15 項目が通ることを確かめる
- **受け入れ条件の確認を `npm run check:telop` に足す:** 既存の 1920x1080 の確認がすべて済んだ後に
  viewport を 1440x795 に切り替え (最後に元へ戻す)、エディットモードで区間 5 つ・テロップ 5 つ・**設定も開いた**
  状態で測る: `#yt-clip-bar` の下端が `innerHeight` 以内 / パネルの下端も `innerHeight` 以内 / パネルの中身が
  溢れていてパネルの中でスクロールできる (`scrollHeight > clientHeight`。設定を開くので必ず溢れる)。
  スクリーンショットを残す

## 仮定と根拠

- 操作ボタンの行と拡大バーはプレイヤー直下に残す — 根拠: ユーザーが選んだ案「右側パネル (推奨)」
  (「操作ボタンと拡大バーは幅が要るのでプレイヤー直下に 1 行だけ残す」)
- パネルに入れるのは区間・テロップ・設定 — 根拠: 依頼文「設定画面だけならまだよかったけど複数区間や
  テロップなど入るとスクロールが必要になってしまい」
- 折り畳みを付ける — 根拠: 選んだ案の説明「折り畳める」
- シアターモードで自動では畳まない — 根拠: 依頼に無い自動化で、判定を誤ると勝手に消えたように見える。
  可逆 (後から足せる)
- 幅 400px — 根拠: YouTube のおすすめ動画の列は 402px 前後 (実機の値。実装時に確かめる)。その上に収まる幅
- 状態の文言の省略表示 — 根拠: 依頼の核 (スクロール不要) を折り返しが食うため。依頼に直接は無いが、
  受け入れ条件を満たすのに要る最小の変更
- 畳んだ状態は保存しない — 根拠: 依頼に無い。YAGNI。可逆

## 検討した選択肢

- **採用: 右側パネル + プレイヤー直下に操作の行と拡大バー** (ユーザーが選択)
- 不採用: 全部を右側パネルへ — 拡大バーが 400px になり、ハンドルの精度が落ちる
- 不採用: 動画の上に重ねる — 動画の一部が隠れ、テロップのプレビューや場面の確認とぶつかる
