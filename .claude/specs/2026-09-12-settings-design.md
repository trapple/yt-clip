# 設定

投稿本文に入れるハッシュタグを設定できるようにする。**設定はこの先も増える**
前提で、項目を 1 つ足すだけで済む形にする。

## 1. 置き場所

バーに **⚙ ボタン**を出し、その場で開くパネルにする。操作をページ内へ集めた
流れと揃う。popup は状態表示だけに縮めたので、そちらには置かない。

## 2. 設定の箱

### 2.1 1 つのオブジェクトにまとめる

`chrome.storage.sync` の **`settings` キー 1 つ**に、すべての設定を持つ。
キーを設定ごとに散らすと、読み出しが増えるたびに `chrome.storage.sync.get` の
呼び出しと既定値の補完を書き足すことになる。

```typescript
export type Settings = {
  /** 投稿本文のテンプレート */
  template: string;
  /** 本文の末尾に付けるハッシュタグ。# は含めない */
  hashtags: string[];
};
```

`template` は今のところ画面から編集できないが、**設定であることに変わりはない**
ので同じ箱に入れる。これまで `template` キーに直接置いていたものを移す。

### 2.2 壊れた値を読んでも落ちない

`chrome.storage.sync` の中身は、古いバージョンが書いたものや、同期で他の端末
から来たものでありうる。**型は保証されない。** 既定値の上に、型の合う項目
だけを重ねる。合わないものは既定値のまま使い、握り潰さず理由をログに残す。

### 2.3 項目を足すときに触る場所を 1 つにする

パネルは `SETTINGS_FIELDS` を並べるだけにする。設定を足すときは
`Settings` に 1 行、`SETTINGS_FIELDS` に 1 要素を足せば画面にも出る。

```typescript
export type SettingsField = {
  /** 入力欄を識別する。DOM の id にも使う */
  key: string;
  label: string;
  /** 入力欄の下に出す短い説明 */
  hint: string;
  /** 保存されている値を入力欄の文字列にする */
  toText(settings: Settings): string;
  /** 入力欄の文字列から、設定の一部を作る */
  fromText(text: string): Partial<Settings>;
};
```

## 3. ハッシュタグ

### 3.1 入力の正規化

空白区切りで受け取り、`#` が付いていなければ付ける。全角空白と読点も
区切りとして扱う。**保存するときは `#` を含めない** — 表示や本文の組み立てで
付ける方が、二重に付く事故が起きない。

```
入力  切り抜き #VTuber、神椿
保存  ["切り抜き", "VTuber", "神椿"]
本文  #切り抜き #VTuber #神椿
```

同じタグが並んだら 1 つにまとめる。順序は入力のまま保つ。

### 3.2 本文への入り方

テンプレートに **`{tags}`** を足し、既定を `{title}\n\n{url}{tags}` にする。

**`{tags}` は自分で区切りを持つ。** 値は空文字か `\n\n#切り抜き #VTuber` の
どちらかになる。テンプレート側に `\n\n{tags}` と書くと、タグが未設定のときに
本文が空行 2 つで終わってしまうため。

### 3.3 投稿のたびに読み直す

本文は投稿のたびに組み立てられるので、`posted` の状態でタグを変えて
「X にもう一度投稿」すると**新しいタグで投稿できる**。録り直しは要らない。

## 4. パネルの見た目

バーの中に開く。配色はバーと同じ自前の変数 (`--ytc-*`) を使う。

```
( IN ) ( OUT ) ( ▶ 範囲を見る ) ( ● 録画 )      ( ⚙ )

┌────────────────────────────────────┐
│ ハッシュタグ                        │
│ [ 切り抜き VTuber              ]   │
│ 空白区切り。# は省略できます        │
│                                     │
│                        ( 保存 )     │
└────────────────────────────────────┘
```

- ⚙ を押すたびに開閉する
- 開いたときに保存済みの値を流し込む
- 「保存」で書き込み、結果を短く出す

## 6. テスト方針

- **正規化** — `#` の有無、全角空白、読点、重複、空入力。純粋関数なので厚く書く
- **`{tags}`** — タグ無しで空文字になること、あるとき区切りを自分で持つこと
- **読み出し** — 保存が空のときに既定値になること、**型の合わない値が
  入っていても落ちないこと**
- **パネル** — 保存済みの値が入力欄に出ること、保存で書き込まれること、
  項目定義を足すと入力欄が増えること
- **見た目** — 単体テストでは検証しない。`docs/manual-check.md` に項目を足す

## 7. この設計で解決しないこと

- **テンプレートの編集** — 箱には入れるが、画面には出さない。要望が出たら
  `SETTINGS_FIELDS` に 1 要素足せば出せる
- **ハッシュタグの妥当性検査** — X が受け付けない文字 (記号・空白) を弾く
  ところまではやらない。入れたものがそのまま出る
