# 0004. 文字起こしの欄の検索は、行を残して当たりに印を付け、↑↓ で飛ぶ

- 状態: 採用 (2026-11-03)
- 補うもの: ADR 0001 の Decision「文字起こしの欄を入口にする」(第 2 版モックの「⌕ 文字起こしを検索」)

## Context

長い配信では欄の行が 8000 ほどになり、スクロールだけでは場面を探せない。第 2 版モックには検索欄だけがあり、
当たった後の見せ方は決めていなかった。

## Decision

- 行は全部残し、当たった語に印を付ける。欄に「2 / 5」と出し、↑ ↓ (Enter / Shift+Enter) で次・前の当たりの行へ
  欄の中をスクロールする (回答 2026-11-03「印を付けて ↑↓ で飛ぶ (推奨)」)
- 当たりは行で数える (同じ行に 2 度出ても 1 件)。今の当たりの行は、ほかの当たりの行より強い印にする
- 探すのは字幕の行の、欄に出している文字 (直した行は直した文字)。手入力の行は探さない (数個で目で見える。
  描くたびに作り直すので印を付け直す仕組みが別に要る)
- 比べるときは NFKC で揃え、英字の大小を区別しない (全角・半角の違いで当たり損ねない)。ひらがなとカタカナは
  区別する
- 打ったら欄の先頭から数えて 1 件目へ飛ぶ。最後の次は最初へ戻る。飛んでも再生位置は動かさない
  (再生は今と同じく行の時刻を押す)。飛んだ後しばらくは再生位置を追うスクロールで引き戻さない
- Esc か ✕ で検索の文字を消し、印を外す。文字起こしが無い・取っている間・取れなかったときは検索欄を押せない。
  録画中も検索はできる (行を読むだけで区間を変えない)

## Considered Options

- 当たった行だけに絞る: 数は一目で分かるが、前後の行と区間の見出しが見えなくなる。Shift の範囲選択や、区間に
  入っている行の見え方と食い違いやすい

## Consequences

- 行の要素は今どおり使い回せる (絞ると、出し入れのたびに見出しと手入力の行の差し込み先も変わる)
- 印は行の文字を text node と印の要素に分けて入れる。文字は今どおり `textContent` で入れ、HTML として解釈しない
- 状態が届いて行の文字が変わっても、検索の文字は残し、当たりを数え直す。今の当たりは行の id で覚え、残っていれば
  その行のまま
