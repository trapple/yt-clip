# リリース前 手動確認チェックリスト

E2E (`npm run e2e`) は「拡張が読み込まれ、IN/OUT UI が出て、popup が録画できる
状態になる」という、**IN/OUT の範囲確定まで**しか自動化していない。実際の録画は
自動化できない。`chrome.tabCapture` は拡張がそのタブに対して呼び出されたことを
要求し、実ユーザーはツールバーのアイコンをクリックして popup を開く操作でこれを
満たすが、Playwright は popup を URL 直接ナビゲーションで開くためこの条件を
満たせず、`getStreamId` が `Extension has not been invoked for the current
page` で失敗する。ブラウザの仕様上の制約であり、実装のバグではない。録画・
プレビュー・X への添付は、タイミングに依存するもの、耳や目で確認するしかない
もの、ログイン済みアカウントが要るものを含め、すべてこのチェックリストで
手動確認する。X への添付はログイン済みアカウントを必要とするため、認証情報を
テストに持たせない方針であえて自動化していない。

## 準備

1. `npm run build`
2. `chrome://extensions` を開き、デベロッパーモードを有効にする
3. 「パッケージ化されていない拡張機能を読み込む」で `dist/` を指定する
4. X にログインしておく

## 通常フロー (MP4 対応環境)

- [ ] YouTube の再生画面に IN / OUT ボタンが表示される
- [ ] IN を押すと popup に開始位置が表示される
- [ ] OUT を押すと「〜秒を録画できます」と表示される
- [ ] 「録画」を押すと開始位置へ移動し、そこから再生が始まる
- [ ] **タブの録画が権限エラーにならない**（`chrome.tabCapture` は拡張がそのタブに対して呼び出されたことを要求する。ツールバーのアイコンから popup を開いた場合にこれが満たされるかを確認する。失敗する場合は manifest への `activeTab` 追加を検討する）
- [ ] **クリップの冒頭が欠けていない** (IN で指定した位置から始まっている)
- [ ] 録画中もタブの音声がスピーカーから聞こえる
- [ ] OUT の位置で録画が止まり、末尾が伸びていない
- [ ] popup でクリップを再生して確認できる
- [ ] 「取り直し」で同じ範囲を録り直せる
- [ ] 「X に投稿」で投稿画面が開き、動画が添付される
- [ ] 本文にタイトルと開始秒つき URL が入っている
- [ ] **投稿ボタンが自動で押されていない**
- [ ] 実際に投稿して、X 上で動画がインライン再生される

## 制約の確認

- [ ] 61 秒以上の範囲を指定するとエラー文言が出て録画に進まない
- [ ] 低画質 (480p 以下) で録画しようとすると画質を上げるよう警告が出る
- [ ] 広告の再生中に録画しようとすると中断され、理由が表示される
- [ ] 録画中に対象タブを閉じると失敗として表示される
- [ ] タブの録画を拒否すると理由が表示される

## degraded path

- [ ] MP4 非対応の環境で「この環境では X に直接添付できません」と表示される
- [ ] その状態でもプレビューでき、WebM をダウンロードできる
- [ ] X の添付に失敗した場合、ダウンロードへ誘導される (クリップが消えない)

## 録画エンジン

単体テストではモックできない `MediaRecorder` / `AudioContext` / tabCapture
インジケータの実挙動。

- [ ] 録画中に `MediaRecorder` を強制的にエラーにしたとき (例: DevTools でタブを
      閉じかける等)、OUT 到達を待たず**即座に** failed 表示に切り替わる
- [ ] 録画開始に失敗したとき、Chrome のタブ共有インジケータ (タブのカメラ/共有アイコン)
      が残留せず消える
- [ ] 正常停止後もインジケータが消え、`chrome://inspect` 等で `AudioContext` が
      close されていることを確認できる (残っていると次回録画で音が二重になる)
- [ ] **`AudioContext` のパススルーが実際にタブ音声を復元しているか**を耳で確認する
      (tabCapture 中は素の状態だと音が消えるため、拡張が戻していることの実機確認)
- [ ] 同じタブで連続して複数クリップを録画しても、タブが重くなる・音が乱れる等の
      リソース蓄積が起きない
- [ ] `recorder/started` の応答が届く前に `recorder/stop` に相当する操作 (OUT へ
      即到達する短いクリップ等) が発生しても、例外が投げられず失敗として処理される
- [ ] 生成された動画が MP4 / WebM いずれの環境でも実際に再生でき、1 秒ごとの
      chunk 分割によるコマ落ち・音ずれがない
- [ ] エラー発生と明示停止 (OUT ボタンや取り直し) のタイミングが近接したとき、
      表示される失敗理由が `InvalidStateError` のような内部例外名にすり替わって
      いない (ユーザー向けの文言のままである)

## YouTube UI

DOM の再描画やタイミングに依存し、単体テストの jsdom では再現しにくい項目。

- [ ] **動画 A で IN → SPA 遷移で動画 B へ → B で OUT** を押すと「動画が変わりました」
      と表示され、A と B をまたいだ誤った範囲では録画されない
- [ ] **`seeking` から `recording` に移るまでの間、動画が本当に進んでいない** (IN の
      位置で止まったまま録画開始を待っている。コマ送り等で確認)
- [ ] シアターモード切替・ミニプレイヤー化などで DOM が再描画されても、IN/OUT バーが
      重複生成されず 1 つだけ存在し、押しても機能し続ける
- [ ] ミニプレイヤー化等で `video` 要素が一時的に取得できないとき、無音のまま
      ハングせず、理由が画面に表示される
- [ ] 低画質 (480p 以下) で録画しようとしたとき、警告は出るが録画自体は継続する
      (録画を止めない)
- [ ] `requestVideoFrameCallback` による停止が OUT 秒に対してどの程度の誤差 (フレーム
      単位) で止まるかを実際に確認する

## X 添付

`X_SELECTORS` の候補配列やテンプレート展開など、実際の X の DOM でしか
検証できない項目。

- [ ] **本文の改行が正しく反映されるか**。テンプレート既定値は `{title}` + 空行 +
      `{url}` でリテラル改行を含むため、X の contenteditable に貼り付けたときに
      1 行へ潰れていないかを重点確認する
- [ ] `input.files` への代入後、X 側のプレビューサムネイルが表示される
- [ ] `X_SELECTORS.fileInput` / `X_SELECTORS.editor` の候補配列のうち何番目が
      実際にヒットしているか (`data-testid` が X 側の変更で変わっていないか)
      DevTools 等で確認する
- [ ] `/compose/` のパス判定が実際の投稿画面 URL と一致する (投稿ダイアログ
      (ポップアップ) と専用コンポーザ (`/compose/post` 等) の両方で確認する)
- [ ] **投稿ボタンが自動で押されていないこと** (自動添付後、送信は必ず手動)

## 全体フロー

複数コンポーネントをまたぐ状態遷移で、単体テストの範囲外になりやすい項目。

- [ ] 動画をまたいで IN を打ち直した後、popup の「録画」ボタンが誤って押せる状態
      (無効化漏れ) になっていないか
- [ ] 録画中に別の YouTube タブで IN を押しても、進行中の録画が中断・破損しない
- [ ] 録画中に popup の進捗表示 (残り秒数・プログレスバー) が実際に減っていく/動く
- [ ] ダウンロード後、「ダウンロード」「取り直し」ボタンが再び操作可能な状態に戻る
- [ ] MP4 非対応環境 (Linux Chrome 等) で WebM への退避が発生し、警告文言が出た
      上でダウンロードできる
